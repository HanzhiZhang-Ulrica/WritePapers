# 逐句修改与表达

## 修改范围与精确替换

- 修改已有稿件时先分析具体障碍，再给准确位置、原文与修改后 code fence 及原因，保留未受影响的已确认内容，并同步处理必要的跨节一致性

**位置：** section、paragraph、准确原句，必要时给当前文件行号。

**原文**

```
这里放当前文件中的完整原句。
```

**修改后**

```
这里放可以直接替换的完整句子。
```

**原因**

说明具体解决的阅读、逻辑、技术或格式问题。避免只写“更专业”“更清晰”。

原句必须来自当前文件，不能重新翻译一遍再当作原文。没有批注且无必要联动的部分保持不动。

已经正确的句子不重新润色，局部问题不触发整节重写。

## 缩短与排版锁定

**移走次要内容 → 删除重复解释 → 合并重复职责 → 精简句子。**

控制修改幅度，保留必要解释；要求少6词就按这个尺度处理。

用户要求缩短时，先确定缩短的目标幅度，保留必要的解释、因果关系、引用、数学符号和视觉编码。

对于要求减少具体词数的任务，应核对实际修改数量。

正文已经排好时，优先采用等长或更短的替换。新的配置说明和推导进入附录。确实需要增加正文信息时，指出其必要性，并从同一区域移走等量冗余。

**字符数或词数减少不能保证页数不变。** 图表浮动、数学换行和段尾变化仍需通过完整编译检查。

## 句内、句间与段间衔接

每个自然段同时检查句内、句间和段间的逻辑关系。

先明确相邻信息之间属于原因、结果、转折、递进、比较、实例还是数据传递，再选择自然的连接方式。

压缩后的文本必须保留“为什么需要这个设计、具体改变什么、结果怎样进入下一步”的解释。

避免把多个技术概念挤进一个虽然简短但难以阅读的长句。

- `Therefore`：后句确实由前句推出。
- `However`：存在需要读者注意的真实转折。
- `For example`：后句是前述概念的具体实例。
- `This score`、`This representation`：明确指代。
- `These results`：指向清楚的一组证据。

“流程先后”可以依靠对象传递表达，不需要每个动作都配一个引导词。

## 术语与格式保真

每篇论文建立核心术语与符号的锁定表，严格区分研究对象、分配单元、计算单元和实验对象。

同一个概念在 Abstract、Introduction、Method、Experiments、Figures 和 Conclusion 中保持一致。

修改 LaTeX 时保留用户指定的宏定义、颜色命令、指标方向、粗体、公式字号和版面要求。

所有数学环境必须合法，公式需要适应实际双栏或单栏排版。

- & 不能出现在普通行内公式中；\small 的作用域需要正确处理

输出应当能够直接复制，用户指定的每段源码排布也属于交付要求。

- 要求 LaTeX 可以直接复制，英文每个自然段保持一行，修改时给出准确原句和替换句

`\eqref` 的行为取决于当前加载的宏文件和包。先读取实际定义，再修复引用。一个 subsection 保留一个语义明确的 label；修改 label 时同步全部引用。

删除表格列时，同时检查 column specification、表头、单位行、数据行和 caption。

## 主语、段落与粗体

适当被动语态也可以使用，不必执行“全文所有句子主动语态”的僵硬规则。

**标题负责定位，段内粗体负责强调关键关系。**

已有 `\paragraph{...}` 时，后面不要再添加一个同级的段首粗体标题。普通段落也不必全部改造成带粗体名称的小卡片。

- 每个较长段落通常只强调一个值得记住的机制或结论

常见需要删除的模式：

```
段首预告将介绍某机制。
中间介绍机制。
段尾再次概括已经介绍该机制。
下一段重新预告整个流程。
```

| 空泛表达         | 更有信息的写法                     |
| ---------------- | ---------------------------------- |
| 提高了整体效率   | 指出减少哪项工作或提高哪个完整指标 |
| 提供灵活性       | 指出哪个对象能够独立选择什么       |
| 增强鲁棒性       | 指出在什么变化范围内保持什么表现   |
| 实现无缝衔接     | 说明前一步产生什么，后一步怎样使用 |
| 显示广泛意义     | 提炼一个能够迁移的设计判断         |
| 结果令人印象深刻 | 给出参照、数值、条件与用途         |

## 场景、目标、冲突、推进与回收

| 叙事技巧       | 论文中的应用                     |
| -------------- | -------------------------------- |
| 场景具体       | 明确 workload、对象与运行环境    |
| 目标明确       | 说明需要同时实现什么             |
| 冲突真实       | 来自实际约束之间的耦合           |
| 每个场景有作用 | 每段必须推进一个必要理解         |
| 信息逐渐具体   | 概念、机制、公式、证据依次展开   |
| 前后呼应       | 引言的问题在实验和结论中得到回答 |

## 正文缩写

- 避免 W4/W8/A8 式正文缩写

- 采用完整位宽表达；公式和代码标识保持准确

- 缩写首次展开

- 包括 TTFT、TPOT、NLL 等读者需要理解的指标

## 批注与确认状态

建立以下状态：

| 状态           | 含义         |
| ------------ | ---------- |
| Accepted     | 作者确认采用     |
| Applied      | 已实际修改      |
| Rejected     | 作者明确拒绝     |
| Deferred     | 延后处理       |
| Data Pending | 等待最终实验     |
| Verified     | 已通过代码或协议确认 |

后续检查使用这些状态。已经拒绝的措辞建议不应不断重新列为“必须修改”；已经确认的实验条件也不应仅凭旧疑点反复要求重查。

## 六轮系统性修改

修改顺序必须从研究与结构开始，最后才是遣词造句。

如果论文的 gap、contributions 或实验归因仍然有问题，先做同义词替换只会浪费大量时间。

| 轮次 | 检查重点与对应规则 | 完成标准 |
| --- | --- | --- |
| 1. Scientific Validity | [成稿与投稿检查](final-checks.md)：实验与技术可靠性、指标、比较条件与证据边界 | 论文没有实质性技术错误、跨配置混用或 unsupported claims。 |
| 2. Research Story | [共同要求](common-rules.md)：研究问题和核心洞察；[研究定位与证据](research-and-evidence.md)：主张、机制、证据与位置 | 能够不用方法名和模块列表，用一段普通语言讲清全文研究故事。 |
| 3. Reader-First Clarity | [共同要求](common-rules.md)：逻辑、对象和机制；逐句修改：句内、句间与段间衔接 | 熟悉相邻领域但尚未阅读该仓库的读者，能够顺着正文理解核心设计。 |
| 4. Writing Style / De-AI | [共同要求](common-rules.md)：语言限制；逐句修改：主语、段落与粗体、术语与格式保真 | 专业、准确、正式、自然，读者能够快速理解句子真正传递的技术信息。 |
| 5. Figures、Tables、References 和版面 | [成稿与投稿检查](final-checks.md)：引用检查、图表与视觉编码、最终 PDF 与验证范围 | 内容与视觉一致，图表可独立理解，LaTeX 编译结果符合提交要求。 |
| 6. 模拟 Reviewer 审查 | [成稿与投稿检查](final-checks.md)：双重可读性与逐句检查；下方问题分类 | 六轮修改后，剩余问题有明确分类，不再反复出现同一批无效建议。 |

## 审查问题分类

| 状态                  | 处理             |
| ------------------- | -------------- |
| Factual Error       | 立即修复           |
| Unsupported Claim   | 调整范围或补证据       |
| Missing Explanation | 增加必要解释         |
| Missing Ablation    | 判断是否影响核心 claim |
| Presentation Issue  | 修改文字或图表        |
| Already Addressed   | 给出已有位置，不重复改    |
| Author Confirmed    | 记录已确认条件        |
| Rejected Suggestion | 保持作者已经确定的选择    |

模拟 reviewer 的判断只是审查工具，不直接等同于真实接收概率。

## 当前版本与多方意见

每次修改前必须打开最新版本。

不能使用两三轮以前的旧句子冒充当前原文。

把不同意见分为：

- 共同指出的实质问题。
- 真正存在分歧的研究判断。
- 纯粹措辞偏好。
- 新发现的有用写作技巧。
- 依据错误版本得出的建议。

对于重要 framing 变化，由作者决定是否采用。

此前已拒绝的全面重写，不能因为另一个模型再次提出就自动恢复。

## 重复收尾

尤其搜索：

```
Together, these results ...
This demonstrates ...
This highlights ...
This underscores ...
```

它们不是绝对禁止的词组，但不能作为每段的固定收尾。

需要有新的结果解释或实际研究认识。
