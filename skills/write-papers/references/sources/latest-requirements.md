## 五、这次最重要的变化

与现有文档相比，我认为你这次真正新增或进一步严格化的要求可以归纳为五个层次：

逻辑不是句子的附属品，而是写作的主体。

每句话都应当在逻辑上连接前后内容，包括句子内部的分句关系。

缩短是精确编辑，而不是重新生成。

控制修改幅度，保留必要解释；要求少6词就按这个尺度处理。

写作质量包含术语、代码和视觉呈现的一致性。

不能只保持语义大致相同，还要保留颜色、排版、公式和对象命名。

论文同时需要连续可读和局部可验证。

人类读者应当理解整个研究故事，审稿人则能够准确检查每个贡献与对应证据。

请在既有写作规范基础上，把以下要求落实到成稿：实际阅读提供的材料，学习其论证推进、信息取舍和解释深度，不能只套章节格式或移植样例的技术主张；最新明确批注应跨轮次、跨章节持续生效，已经纠正的范围、措辞和逻辑问题不得再次出现。**先区分整体目标、具体研究问题和核心洞察**：整体目标说明需要同时满足的实际要求；研究问题从真实现象与已有设计的结构性约束中推出，明确本文要改变的决策对象或组织关系，不能重复“提高效率并保持质量”；核心洞察必须紧接着回答研究问题，说明改变什么关系、由此获得什么能力，不能再次复述卖点口号，也不能用“别人没有做过”代替创新依据。引言第一句话直接引出核心目标及其矛盾，以有引用支持的真实应用说明价值，避免泛谈领域重要性；研究范围与已确认内容保持一致，不擅自缩窄到某种特殊任务、输入长度或硬件，也不把综合质量等同于单一评价指标；第一段内就要交代相关操作、定性现象及其造成的问题，不堆观察数据。第二段按方法类别推进，每类在同一句或紧接的一句中说明“做什么、受什么具体约束、因此增加哪项成本或损害哪种能力”，不能只写“粒度不足”“存在取舍”“增加开销”而让读者猜后果，再据此引出本文特有的研究问题。    How To Write Papers(9) **转折、因果、递进和阶段切换必须有明确承接**，按真实关系使用 However、Therefore、Further 等连接词或带具体对象的承接句，不能把各自正确的句子直接拼接，也不能只添加连接词而省略中间推理。所有新对象和术语先交代含义与用途，普通操作直接点名，避免为显得专业而增加抽象概念；“这些成本”“这一现象”“该配置”等指代必须唯一明确，候选是什么、误差相对谁、预算约束什么、范围和边界划分什么，都要在读者第一次需要理解时解释清楚。每项关键机制都应说明何时对什么对象做什么、产生什么、带来什么具体收益，以及产物怎样进入下一步，按照实际依赖顺序介绍准备、选择、执行和复用，不能让读者自行补全对象来源与因果关系。   从代码仓库到投稿论文：研究定位、结构设计与写作指引 引言的方法总述只保留核心机制及其作用，参数、边界定义、数值技巧、线程和缓存细节进入 Method 或 Appendix；困难应解释核心认识落地时必须同时满足的要求，并与后续解法对应。贡献默认组织为三项职责独立、共同支撑主要认识的交付，分别说清建立的能力、解决的关键决策和实现的实际价值；联合设计应强调整体组织及各部分的协同，不擅自把某个档位、参数或实现技巧提升为单独卖点。    paper_ICLR2027_AlignQuant(7) 引言结果段只选核心评价维度各一个最有分量的结果，例如质量与效率各一个最佳结果，保留必要参照、指标和适用条件，不罗列全部模型、硬件、baseline、实验范围和消融，也不把局部最佳写成全面优势。Related Work 应比引言更深入地解释选择对象、判据、粒度和执行关系，按技术类别组织，每个类别句主动寻找多篇真正支持共同描述的代表工作，避免一个类别只有一篇论文，也避免为凑数量堆引用；指定 baseline 必须在相关类别中得到引用，其对应的论证应与后文比较形成闭环，但 baseline 清单不是文献范围的上限。应用背景和已有技术均需有语义匹配的引用；优先采用成熟、可靠的文献，近两个月的新稿谨慎使用，排除当轮刚提交 ICLR 的未录用工作；沿用已提供的 BibTeX key，缺少条目时保留明确引用占位并另列准确标题，不自行编造或补写条目。图尚未确定时只保留图环境、标签和中性图注占位，不提前规定面板、布局或图中结论。指定只做文字写作时，以已确认的研究设计推进有依据的正文，未完成的结果留占位，不反复转向实验设计、代码核验或把开发状态写成免责声明。文字应正向、直接、有具体对象，删除仅为预防质疑而存在的句子，同时保持事实和必要条件准确；禁用 not…but、rather than、not only 等否定式包装及句中插入破折号，不主动使用 static，减少重复主语、同形句式、无必要的新术语与重复总结。摘要和结论的收束必须增加可迁移的设计认识，说明读者以后可以据此作出什么不同选择，不能再说一遍“更快且质量更好”。修改已有稿件时先分析具体障碍，再给准确位置、原文与修改后 code fence 及原因，保留未受影响的已确认内容，并同步处理必要的跨节一致性；交付前主动逐句检查“这是谁、为什么此时出现、与谁比较、具体收益是什么、与上一句如何连接、是否推进了新的理解”，把问题解决在正文里，而不是只在分析中解释正确、成稿继续重复同样的错误。
